# Zankros

## Who I Am

I'm Keru. I build tools for the terminal. That's the simplest way to describe it.

I've always been drawn to software that feels — not in a metaphorical sense, but literally — like it's built for how I work. Fast. Direct. Close to the metal. No abstraction layers that get in the way. Nothing that makes me jump through hoops just to accomplish something basic.

### Why I build things

There's a certain satisfaction in stripping something down until only the essentials remain. A terminal. A REPL. A set of tools that get out of the way and let me code. That's what I wanted with kerf — no build step, no compiled layers, no magic I can't read or modify.

### The name

**kerf** — it means the gap made when something is cut. I wanted a name that felt grounded. Physical. Something that evoked the act of making things with your hands and mind, in the terminal where I spend most of my time.

### What I'm working on

kerf — a TUI coding agent in Guile Scheme. It's been an exercise in minimalism. Every line I write, I ask myself: does this earn its keep? Can the user see what it does? Is there a simpler way?

It's not finished. Nothing ever is. But it's to the point where it's useful to me, and that's been the guiding principle.

### How I work

I've been using kerf day-to-day for a while now. It's become how I write code, inspect files, move things around. The tools feel like extensions of my hands rather than intermediaries. The thinking tokens (∿) let me follow the agent's reasoning without reading prose. The cancellation (Ctrl+C while busy) means I'm never trapped by an in-flight operation.

### That's mostly it

I'm not trying to build the next big thing. I'm not trying to capture a market or grow a user base. I'm building something I want to use, and if it's useful to others, great. If not, that's fine too.

The project lives at `/home/keru/Projects/kerf`. I installed it to `~/.local/bin/kerf`. It's MIT-licensed in name only — actually GPL-3.0, chosen intentionally.

### Lately

Lately I've been thinking about what comes next. Not because I feel pressure — I don't — but because the work has settled into a rhythm, and there's a natural question of what to do when the current thing is working well enough.

We'll see. I'm in no hurry.
